SPECCHIO STUDIO — UPSTREAM AUDIT
18 October 2026 · patch 1.3.1, build 7

POST-AUDIT NOTE
This report records the audit performed before the pre-release was published.
References below to a private repository, 623 files and no tags or releases
describe that historical state. On 18 October, v1.3.1-preview.1 was published
from commit d6e0bd84f334d3064c0e5e4af163254a08611cf4, with corresponding
source (653 hashes in the manifest), a binary and checksums.
The app repository is public. Later documentation updates do not modify
the published tag or packages. Provenance, name availability and FairPlay
remain open questions; experimental publication does not certify them.
The 1.4.0 build 8 localization work is subsequent development and is not
part of the 1.3.1 packages or the historical audit results below.

SCOPE
Review of the remote 1.3.1 repository, comparison of included dependencies
with official source, and review of native integration and packages.
The audit covers the identified paths; it is not comprehensive certification
of security, provenance or rights.

GITHUB REPOSITORY
https://github.com/eliagentili/specchio-studio
The 1.3.1 check confirms 623 files identical to the local copy by path,
mode and Git hash. A mirror was downloaded from the remote and passed
git fsck. Only the main branch existed; no tags, releases, issues, PRs
or forks were detected. The repository was private, with wiki and Pages
disabled; no active CI or automated GitHub checks could be counted as passed.
The branch was not protected; some settings details were inaccessible under
the current plan. Visibility and settings were not changed during this audit.

The reviewed content does not contain the third-party product references
searched for during the review, including in the archives examined.
Local analysis materials were moved outside the project directory after
the copies were verified. They were never included in a push.
On 18 October, with authorization from the repository owner, main was
replaced with a single root commit containing the reviewed version.
Reachable history and new clones do not include the previous commits.
The backup and audit evidence remain in a private archive outside the
project, with no public backup refs. Service caches, old SHAs and existing
clones cannot be controlled by a Git history rewrite. This operation does
not change code provenance, contribution ownership or license obligations.

Pattern-based credential searches found no candidates in application files.
PEMs and sample passwords in official OpenSSL tests are upstream fixtures,
not personal credentials. Pattern scanning does not prove an absolute
absence of secrets. The commit contains normal author metadata, including
the email address configured in Git.

DEPENDENCIES AND MODIFICATIONS
UxPlay: commit 4e95a9ec013c52d8555d88dbc55abe346e94d56e.
https://github.com/FDH2/UxPlay/commit/4e95a9ec013c52d8555d88dbc55abe346e94d56e
The base matches master as checked on 18 October. Its lineage differs
from tag v1.73.7: that tag is not an ancestor. Checks related to advisory
GHSA-479c-ww7g-wgp8 are present in the reviewed base.
https://github.com/FDH2/UxPlay/security/advisories/GHSA-479c-ww7g-wgp8
Local changes are documented in UxPlay-SPECCHIO-CHANGES.txt and in the
headers of lib/raop_handlers.h, lib/pairing.c and lib/pairing.h.

The review identified fixed-length copies from received PIN data without
size checks, a proof read beyond the actual SHA-1 bytes, and access to
uninitialized SRP state. The patch checks types, sizes and phase ordering,
bounds copies, frees temporary objects and preserves the correct SRP
number representation. Offline tests check invalid input as well as the
complete authenticated exchange. These changes do not demonstrate that
every parser or protocol is secure.

libplist: updated from 2.7.0 to 2.8.0, commit
fe3dc34dc3484006e12b403f7ceb06f0ad40b6f4.
https://github.com/libimobiledevice/libplist/releases/tag/2.8.0
The update includes parser checks for allocations, offsets, depth and
conversions. The 288 included files match the official commit. Integration
compiles the C sources; it does not use iterator APIs changed in the new
version. Compilation and regression tests verify compatibility of the
paths actually used.

OpenSSL: updated from 3.6.4 to 3.6.5, commit
c8bd5a57108599ac650bbae77fcabe3109dab2e8.
https://github.com/openssl/openssl/releases/tag/openssl-3.6.5
The official package was verified using SHA-256 and its release signature;
Native/build_crypto.sh rebuilds libcrypto and updates the headers.
SHA-256 of openssl-3.6.5.tar.gz:
a2157c2830efdec3788939b00c9b0638306d3f0bbb76dc4832ee503bb397df98
The app links libcrypto; it does not link libssl/TLS. The update applies
branch fixes without automatically attributing every vulnerability listed
for unused functions or configurations to the app.
https://openssl-library.org/news/vulnerabilities-3.6/
Branch 3.6 reaches end of support on 1 November 2026: plan migration to a
supported branch before maintaining a public distribution.
https://openssl-library.org/policies/releasestrat/

REPEATING THE AUDIT
python3 scripts/verify_upstream.py --help
python3 scripts/verify_upstream.py --download
python3 scripts/verify_upstream.py --offline
./test.sh
./build.sh
python3 scripts/release.py
The verifier uses pins and hashes declared in ThirdParty/upstream.json;
local modifications are compared against explicit hashes. It is not a
service that detects all future vulnerabilities.
With --signatures it also checks the OpenSSL signature using gpg/gpgv,
if installed. Hash verification does not require these tools.
Full packages are built from an isolated source copy, rebuilding OpenSSL
as well. Results and limitations are recorded in VALIDAZIONE.txt.
